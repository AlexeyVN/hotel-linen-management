# Безопасность

## Поддерживаемые версии

Поддерживается текущая ветка `main` (v2.x). Старые снапшоты — только для восстановления, не для эксплуатации.

## Сообщить об уязвимости

Не создавайте публичный issue с секретами или персональными данными. Свяжитесь с владельцем репозитория приватно и укажите:

- версию/коммит, шаги воспроизведения, влияние;
- затронутые файлы/маршруты;
- есть ли данные клиентов.

## Модель безопасности

- Вход: next-auth (JWT, 8 часов), bcrypt, блокировка после 10 ошибок, rate limit.
- Права проверяются на сервере (`permissionProcedure`), а не только скрытием UI.
- Фото, QR и логотип лежат вне `public`; фото и QR отдаются через API с проверкой прав; логотип публичный (нужен на странице входа).
- Пароль 1С шифруется AES-256-GCM ключом из `NEXTAUTH_SECRET`.
- Webhook 1С принимает только `X-Webhook-Token`; токен хранится зашифрованным и заменяется в админке.
- SQLite-файл, `.env`, `storage/`, `backups/` не должны попадать в GitHub.

## Обязательно при развёртывании

- Сменить демо-пароли `admin/manager/maid`.
- Задать случайный `NEXTAUTH_SECRET` (32+ байта), не публиковать `.env`.
- Использовать HTTPS и доверенный сертификат; не открывать Node-порт в интернет.
- Ограничить файловые права на `data/`, `storage/`, `backups/`.
- Настроить бэкапы и проверять восстановление.
- Включить Dependabot/secret scanning в GitHub.

## Если секрет попал в репозиторий

Смените значение (сессия/пароль/токен) и очистите историю (`git filter-repo`). Удаление файла в новом коммите не убирает секрет из истории.
