# Установка на Open Server Panel — пошагово для новичка

Эта инструкция проведёт от пустого Windows-компьютера до работающей системы учёта белья «Белая пристань» на Open Server Panel (OSPanel). Опыт администрирования серверов не нужен, но команды нужно выполнять внимательно.

**Что получится:** приложение открывается в браузере по адресу `https://hotel` (или `http://localhost:3000`), в него можно войти, завести номера, склад и сотрудников.

**Время:** 30–60 минут в первый раз.

## Быстрый старт: install.cmd

Если не хочется вводить команды вручную, в корне архива есть `install.cmd`. Запустите его **от имени администратора** — скрипт по шагам спросит пути, адрес, подтвердит установку зависимостей, миграции, seed и сборку.

Скрипт не устанавливает Node.js и OSPanel автоматически: он откроет страницу загрузки Node.js и попросит установить программу, затем продолжит.

Проверка окружения без изменений:

```cmd
install.cmd check
```

Ниже — та же установка вручную, если вы хотите контролировать каждую команду.

---

## 0. Что понадобится

- Windows 10 или 11, 64-бит.
- Права администратора компьютера — для установки программ, создания junction-ссылок и правил брандмауэра.
- Свободное место: около 2 ГБ.
- Интернет для скачивания Node.js, OSPanel и npm-зависимостей.

Скачайте заранее:

1. **Node.js 24 LTS для Windows (x64)** — <https://nodejs.org/en/download>. Нужен установщик `.msi`, не «portable zip».
2. **Open Server Panel 6.5.1** — <https://ospanel.io/>. Устанавливайте в стандартную папку `C:\OSPanel`.
3. **Архив проекта** `hotel-linen-management-v2.2.0-open-server.zip` — он выдаётся вместе с инструкцией. В архиве уже есть исходники, документация и эта инструкция.

Git не нужен. Все команды выполняются в **PowerShell** или **командной строке** (cmd). Если команда не находится, проверьте, что терминал открыт заново после установки Node.js.

---

## 1. Установите Node.js

1. Запустите скачанный `.msi`.
2. Оставляйте настройки по умолчанию, обязательно включите добавление Node.js в `PATH`.
3. После установки откройте новое окно PowerShell и проверьте:

```powershell
node -v
npm.cmd -v
```

Ожидаемо: `v24.x.x` и `11.x.x` или новее. Если команды не найдены — перезагрузите компьютер и проверьте снова.

> В PowerShell иногда запрещён запуск `npm.ps1`. Поэтому в инструкции используется `npm.cmd` и `npx.cmd` — это нормально и безопасно.

---

## 2. Установите и запустите Open Server Panel

1. Установите OSPanel в `C:\OSPanel`.
2. Запустите **OSPanel**.
3. Включите **Apache** (и PHP не обязателен для этого приложения, но OSPanel удобно использовать как единую панель).
4. Убедитесь, что OSPanel запущен и его значок виден в трее.

Позже мы создадим домен `hotel` и настроим проксирование на Node-приложение.

---

## 3. Положите проект в папку OSPanel

1. Распакуйте архив так, чтобы получилась папка:

```text
C:\OSPanel\home\hotel\
```

2. Внутри должны быть:

```text
C:\OSPanel\home\hotel\app\
C:\OSPanel\home\hotel\docs\
C:\OSPanel\home\hotel\deploy\
C:\OSPanel\home\hotel\README.md
```

3. Не используйте путь с русскими буквами и пробелами — это уменьшит количество проблем с Node.js.

---

## 4. Создайте файл настроек `.env`

1. Откройте PowerShell.
2. Перейдите в папку приложения:

```powershell
cd C:\OSPanel\home\hotel\app
```

3. Скопируйте шаблон:

```powershell
Copy-Item .env.example .env
notepad .env
```

4. В открывшемся Блокноте заполните:

```env
DATABASE_URL="file:../data/app.db"
NEXTAUTH_URL="http://localhost:3000"
NEXTAUTH_SECRET="сюда-вставьте-длинную-случайную-строку"
TZ="Europe/Moscow"
LOG_LEVEL="info"
```

5. Сгенерируйте секрет. Выполните в PowerShell:

```powershell
node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"
```

Скопируйте полученную строку в `NEXTAUTH_SECRET` **без кавычек внутри** и сохраните файл.

> `.env` — секрет. Не отправляйте его в мессенджеры, не выкладывайте на GitHub и не копируйте в архив для передачи.

Пока оставьте `NEXTAUTH_URL` как `http://localhost:3000`: сначала проверим приложение напрямую, а домен настроим позже.

---

## 5. Установите зависимости

В том же окне PowerShell, в папке `app`:

```powershell
npm.cmd ci
```

Это скачает библиотеки проекта. Займёт несколько минут. Если появилась ошибка про сеть — проверьте интернет и повторите команду.

---

## 6. Создайте базу данных

По очереди выполните:

```powershell
npx.cmd prisma generate
npx.cmd prisma migrate deploy
npx.cmd prisma db seed
```

Что это значит:

- `generate` — готовит Prisma Client;
- `migrate deploy` — создаёт таблицы базы данных;
- `seed` — заполняет базу демонстрационными данными: 10 номеров, склад, тестовые пользователи.

`seed` нужен **только при первой установке**. При обновлении существующей системы его не запускайте, иначе демо-данные могут смешаться с рабочими.

После выполнения появится файл `C:\OSPanel\home\hotel\app\data\app.db`.

---

## 7. Соберите и запустите приложение

```powershell
npm.cmd run build
npm.cmd start
```

`npm.cmd start` запускает сервер на порту `3000`. **Не закрывайте это окно**, пока работаете с системой. Для остановки нажмите `Ctrl+C`.

Откройте в браузере:

```text
http://localhost:3000
```

Должна открыться страница входа.

Демо-пользователи:

| Логин | Пароль | Роль |
|---|---|---|
| `admin` | `Admin123!` | Администратор |
| `manager` | `Manager123!` | Менеджер |
| `maid` | `Maid123!` | Горничная |

**Сразу после первого входа смените все три пароля** в разделе «Настройки → Пользователи». Это не демонстрационный сайт, а рабочая система.

---

## 8. Настройте домен в OSPanel

Сейчас приложение работает на `localhost:3000`, но OSPanel должен перенаправлять запросы с красивого адреса на этот порт.

1. В OSPanel откройте раздел доменов и создайте домен `hotel` (или `hotel.local`).
2. Укажите корневую папку проекта `C:\OSPanel\home\hotel`.
3. Включите для домена HTTPS, если хотите устанавливать PWA на телефон.
4. Включите проксирование (backend) на `127.0.0.1:3000`.

Если OSPanel использует шаблон `Host_Proxy`, этого достаточно. Если настраиваете Apache вручную, добавьте в конфигурацию домена:

```apache
ProxyPreserveHost On
ProxyPass        / http://127.0.0.1:3000/ retry=0
ProxyPassReverse / http://127.0.0.1:3000/
```

Нужны модули Apache `mod_proxy` и `mod_proxy_http`.

Если используете Nginx:

```nginx
location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

Проверьте, что `http://hotel` (или `https://hotel`) открывает страницу входа, а не стандартную страницу OSPanel.

### Важно: статические файлы OSPanel

OSPanel/Apache при проксировании может отдавать файлы с расширениями (`.js`, `.css`, `.png`) напрямую из `DocumentRoot`, а не через Node. Чтобы стили, картинки и PWA работали, **один раз** выполните в командной строке от имени администратора:

```cmd
mklink /J C:\OSPanel\home\hotel\_next  C:\OSPanel\home\hotel\app\.next
mklink /J C:\OSPanel\home\hotel\icons  C:\OSPanel\home\hotel\app\public\icons
copy C:\OSPanel\home\hotel\app\public\sw.js C:\OSPanel\home\hotel\sw.js
if exist C:\OSPanel\home\hotel\manifest.webmanifest del C:\OSPanel\home\hotel\manifest.webmanifest
```

Пояснение:

- `_next` — собранные стили и JavaScript;
- `icons` — иконки приложения;
- `sw.js` — service worker для PWA;
- `manifest.webmanifest` **не копируем**: в этой версии он динамический и доступен по `/api/manifest`.

После пересборки приложения (`npm run build`) ссылки `_next` и `icons` обновлять не нужно. Копию `sw.js` нужно обновлять, если вы обновляли приложение.

---

## 9. Смените адрес в `.env`

Когда домен заработал, вернитесь в `app\.env` и измените:

```env
NEXTAUTH_URL="https://hotel"
```

Для локального домена без HTTPS:

```env
NEXTAUTH_URL="http://hotel.local"
```

Сохраните файл и перезапустите Node-сервер (`Ctrl+C`, затем снова `npm.cmd start`).

`NEXTAUTH_URL` должен точно совпадать с адресом, по которому вы открываете систему. Иначе вход, QR-коды и ссылки будут работать неправильно.

---

## 10. Первая настройка системы

Войдите как `admin` и пройдите по пунктам:

1. **Настройки → Пользователи** — смените пароли, создайте реальных сотрудников.
2. **Настройки → Общие настройки** — укажите название отеля, ответственного, при необходимости загрузите логотип.
3. **Настройки → Номера и типы комнат** — проверьте этажи, номера и типы комнат.
4. **Склад → Справочник** — замените демонстрационные позиции на реальные.
5. **Склад → Склад** — внесите начальные остатки.
6. **Настройки → Роли** — проверьте права менеджера и горничной.
7. **Настройки → Интеграция 1С** — включайте только после проверки с внедренцем 1С.

Название отеля из «Общих настроек» автоматически меняет заголовок вкладки браузера, описание и webmanifest. Для уже установленного на телефон приложения имя может обновиться не сразу — иногда требуется переустановить PWA.

## 11. Телефон, HTTPS и PWA

PWA (установка на домашний экран) требует **HTTPS**. По `http://<IP-адрес>` она не установится — это ограничение браузеров.

1. В OSPanel включите HTTPS для домена.
2. Установите корневой сертификат OSPanel на телефон (Android: «Настройки → Безопасность → Установить сертификат»).
3. Откройте `https://hotel` на телефоне.
4. Меню браузера → «Добавить на главный экран» / «Установить приложение».

Если телефон не открывает сайт:

- проверьте, что телефон и компьютер в одной сети;
- разрешите Apache порты 80/443 в брандмауэре Windows (от имени администратора):

```powershell
New-NetFirewallRule -DisplayName "Hotel Apache 80/443" -Direction Inbound -Protocol TCP -LocalPort 80,443 -Action Allow -Profile Private,Public
```

Не открывайте порт `3000` в интернет: наружу должен смотреть только Apache/HTTPS.

## 12. Остановка и автозапуск

Остановка:

```powershell
Ctrl+C
```

или закройте окно с `npm.cmd start`.

Запуск вручную:

```cmd
C:\OSPanel\home\hotel\deploy\start.cmd
```

Для автозапуска можно добавить ярлык `deploy\start.cmd` в автозагрузку Windows. Не запускайте два экземпляра одновременно: второй не сможет занять порт `3000`.

---

## 13. Резервные копии

Перед изменениями и раз в неделю делайте копию:

```cmd
C:\OSPanel\home\hotel\deploy\backup.cmd
```

Файл появится в `C:\OSPanel\home\hotel\app\backups\app-<дата>.db`.

Восстановление — только при остановленном сервере:

```cmd
C:\OSPanel\home\hotel\deploy\restore.cmd C:\OSPanel\home\hotel\app\backups\app-20261117-120000.db
```

Не копируйте файл `app.db` «на горячую» при работающем сервере: SQLite может записать неполную копию. Используйте `backup.cmd`.

---

## 14. Обновление приложения

1. Сделайте бэкап: `deploy\backup.cmd`.
2. Остановите сервер (`Ctrl+C`).
3. Замените папку `app` новой версией, **сохранив** `app\.env`, `app\data`, `app\storage` и `app\backups`.
4. В папке `app` выполните:

```powershell
npm.cmd ci
npx.cmd prisma generate
npx.cmd prisma migrate deploy
npm.cmd run build
npm.cmd start
```

5. Скопируйте обновлённый `sw.js`:

```cmd
copy C:\OSPanel\home\hotel\app\public\sw.js C:\OSPanel\home\hotel\sw.js
```

6. Откройте сайт, проверьте вход и разделы.

`prisma db seed` при обновлении **не запускайте**.

## 15. Если что-то не работает

| Симптом | Что проверить |
|---|---|
| `node`/`npm` не найдены | Node.js установлен? Откройте новое окно PowerShell, перезагрузитесь |
| `npm.cmd ci` падает | Интернет, Node 24, папка `app` — та ли это папка |
| `prisma` не подключается к БД | В `.env` должно быть `DATABASE_URL="file:../data/app.db"`; папка `app\data` существует |
| Сайт открывает страницу OSPanel | Домен не проксирует на `127.0.0.1:3000`; проверьте ProxyPass/backend |
| Нет стилей или картинок | Создайте junction `_next` и `icons`, проверьте права администратора |
| PWA не устанавливается | Нужен HTTPS; проверьте сертификат и `NEXTAUTH_URL` |
| Не работает вход | `NEXTAUTH_URL` не совпадает с адресом в браузере; проверьте `NEXTAUTH_SECRET` |
| Порт 3000 занят | Уже запущен другой Node; остановите его, не запускайте второй |
| `database is locked` | Работают два экземпляра приложения; оставьте один |
| После смены названия старый title | Обновите страницу; для установленного PWA — переустановите приложение |
| Ошибка 503/404 после обновления | `npm run build`, junction `_next`, копия `sw.js`, перезапуск Node |

Полезные логи:

```text
C:\OSPanel\home\hotel\app\logs\server.log
```

---

## 16. Безопасность — коротко

- Смените все демо-пароли.
- Не публикуйте `.env`, `data`, `storage`, `backups`.
- `NEXTAUTH_SECRET` — длинная случайная строка, только в `.env`.
- Наружу — только HTTPS-прокси; порт `3000` не открывайте.
- Делайте бэкапы и проверяйте восстановление.
- Не включайте 1С-обмен, пока контракт не проверен на тестовом контуре.

---

## 17. Что входит в сборку

В архиве `hotel-linen-management-v2.2.0-open-server.zip`:

- `app/` — приложение;
- `docs/` — эта инструкция и остальная документация;
- `deploy/` — запуск, бэкап, восстановление;
- `brand/` — логотипы и иконки;
- `README.md`, `LICENSE`, `NOTICE`.

База данных, `.env`, загруженные фото и логи в архив **не входят**. Они создаются при установке и остаются на вашем компьютере.

Если что-то пошло не так, начните с раздела 15 и не удаляйте папку `data` — там рабочая база.
