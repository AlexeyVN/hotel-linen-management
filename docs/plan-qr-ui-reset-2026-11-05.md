# План: сброс старого QR при смене позиции/номера

Дата: 2026-11-05. Статус: **реализовано и выложено на `https://hotel`**.
Утверждённые варианты: показывать сохранённую метку нового объекта; при смене формата/размера очищать предпросмотр и просить перегенерировать; блокировать кнопку и игнорировать поздний ответ.
Проблема: на `/admin/qr` после генерации метки для одной позиции при выборе другой остаётся старый QR и старая ссылка «Скачать».

---

## 1. Причина (по коду)

| Место | Сейчас | Следствие |
|---|---|---|
| `components/qr-admin.tsx` — селект «Объект»/«Конкретный» | при смене `objectType` вызывается `setResult(null)`; при смене `objectId` — **только `setObjectId`** | старый `result` остаётся на экране |
| `qr-admin.tsx` — `result` | хранит `payload/dataUrl/id` без идентификатора объекта | нельзя проверить, к какому объекту относится метка |
| `qr-admin.tsx` — параметры формата/размера | изменение не сбрасывает `result` | предпросмотр может не соответствовать выбранному формату |
| `qr-admin.tsx` — `handleGenerate` | асинхронный ответ сразу `setResult` | при быстрой смене объекта ответ по старому объекту может «вернуться» и снова показать чужой QR |
| `qr.status` | обновляется при смене объекта | статус сохранённой метки правильный, но предпросмотр — старый |

Это не ошибка хранения (B работает), а состояние UI: результат не связан с текущим выбором.

---

## 2. Варианты решения

### Вариант A — «предпросмотр привязан к выбору» (рекомендуется)

1. Хранить результат вместе с ключом выбора:
   ```
   generated: { key, id, payload, dataUrl, imageUrl, payloadFormat, imageFormat, code } | null
   key = `${objectType}:${objectId}:${payloadFormat}:${imageFormat}:${size}`
   ```
2. Рендерить предпросмотр только если `generated.key === currentKey`. При любом изменении объекта или параметров старый блок скрывается автоматически.
3. После `mutateAsync` проверять, что ключ запроса всё ещё равен текущему; иначе игнорировать ответ (защита от гонки).
4. Если для выбранного объекта уже есть сохранённая метка (`qr.status`), показывать её изображение с подписью «Сохранённая метка»; если метка «устарела» — предупреждение и кнопка перегенерации.
5. Кнопка «Скачать» показывается только для актуального результата.

**Плюсы:** старое изображение не появляется ни при смене объекта, ни при смене формата, ни при гонке; сразу видна сохранённая метка нового объекта.
**Минусы:** чуть больше логики в компоненте (ключ + проверка ответа).

### Вариант B — минимальный сброс

- В обработчике смены объекта и в `useEffect` на `[objectType, objectId, payloadFormat, imageFormat, size]` вызывать `setResult(null)`.
- Дополнительно после генерации сравнивать `objectId` с текущим (или блокировать кнопку на время запроса).

**Плюсы:** 5–10 строк, низкий риск.
**Минусы:** при гонке ответ может снова показать чужой QR, если не добавить проверку; нет автоматического показа сохранённой метки.

### Вариант C — пересоздавать блок по `key`

- Обернуть форму/предпросмотр в компонент с `key={objectType+objectId+params}`; при смене React сбрасывает локальное состояние.

**Плюсы:** минимум кода.
**Минусы:** сбрасываются все локальные состояния (включая ошибки/уведомления), возможна потеря введённых параметров; менее предсказуемо для UX.

---

## 3. Рекомендация

**Вариант A.** Он закрывает и исходный баг, и гонку, и несоответствие формата, а также делает страницу удобнее: при выборе объекта сразу видно, есть ли у него сохранённая метка.

## 4. Файлы и проверки

| Файл | Изменение |
|---|---|
| `components/qr-admin.tsx` | ключ выбора, сброс/скрытие старого результата, проверка ответа, показ сохранённой метки |
| API/БД | без изменений |

Проверки (Playwright):

1. Сгенерировать QR для 101 → выбрать 102: старый QR исчезает; если у 102 есть сохранённая метка — показывается она, иначе «метки нет».
2. Сменить формат PNG → SVG после генерации: старый PNG не показывается; предложено перегенерировать.
3. Сгенерировать 101, быстро переключить на 102 до ответа: на экране не появляется QR 101.
4. Скачивание доступно только для актуальной метки; после смены объекта старая ссылка недоступна.
5. Статус «устарела»/«актуальна» и сохранённая метка отображаются корректно.
6. Регрессия: build и тесты.

## 6. Реализация и проверка

- `qr-admin.tsx`: результат хранится с `objectKey`/`paramKey`; при несовпадении не рендерится. `paramsDirty` скрывает предпросмотр при смене формата/нагрузки/размера. После ответа проверяется `selectionKeyRef`; поздний ответ по старому объекту отбрасывается. Кнопка блокируется на время запроса.
- Для выбранного объекта без нового результата показывается сохранённая метка (`qr.status`), если она актуальна; устаревшая — предупреждение.
- Playwright: 101 → сохранённая метка; переход на 102 — старый QR 101 исчез, показана метка 102; смена формата — предпросмотр скрыт; позиция без метки — пустое состояние. 0 ошибок страницы.
