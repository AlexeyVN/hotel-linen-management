# План доработок: номера, справочник, цена/дата (решения заказчика учтены)

Дата: 2026-11-05. Статус: **8A и 8B выполнены и выложены на `https://hotel`**.
Запрос: 1) добавление/удаление номеров; 2) справочник позиций с ценой, примечанием и количеством; добавление на склад вручную с ценой; раздача/возврат/списание без цены; поле «Дата» с выключаемым отображением; инвентаризация с учётом цены и даты поступления.

## 0. Решения заказчика (2026-11-05)

| Вопрос | Решение | Следствие |
|---|---|---|
| Себестоимость | **Текущая цена справочника** | Партии/FIFO не вводим. Стоимость = остаток × текущая цена позиции. Историческая стоимость пересчитывается при изменении цены — это осознанное упрощение |
| «Количество» в справочнике | **Текущий остаток read-only** | Количество вводится при добавлении на склад; двух разных количеств нет |
| Объём | **Двумя шагами 8A → 8B** | 8A — справочник/номера/цена/дата; 8B — оценка в инвентаризации и отчётах, Excel, 1С-поля |
| Дата | Глобальная настройка отображения | `ui.showDates`, по умолчанию включена; дата хранится и используется в расчётах всегда |
| Цена горничной | Скрыта | В мобильном кабинете — только количества |

**Что теряем без партий:** нельзя узнать, по какой цене пришла конкретная единица и как менялась стоимость запаса. Если позже понадобится — партии добавляются отдельным этапом без изменения текущих данных (см. §9).

## 2. Модель данных

### 2.1 Справочник (`Item`)

| Поле | Тип | Правило |
|---|---|---|
| `priceKopecks` | `Int @default(0)` | Цена за единицу в копейках, UI — рубли |
| `note` | `String?` | Примечание |

Количество не хранится в справочнике — показывается текущий остаток склада.

### 2.2 Документы

| Модель | Поле | Назначение |
|---|---|---|
| `Operation` | `documentDate DateTime @default(now())` | Дата документа (приёмка — дата поступления, выбирается; остальные — сегодня) |
| `WarehouseInventory` | `lastReceiptAt DateTime?` | Дата последнего поступления позиции (для склада и инвентаризации) |
| `OperationItem` | без изменений | Цена не дублируется: берётся из справочника на момент отчёта |

### 2.3 Настройка дат

`Setting`: `ui.showDates` (`true` по умолчанию). При выключении колонки «Дата» скрываются в складе, документах, инвентаризации, отчётах; расчёты не меняются.

### 2.4 Права

Новые права: `catalog.manage` (ADMIN/MANAGER) и `settings.ui` (ADMIN/MANAGER). Итого 18.

### 2.5 Миграция и бэкфилл

1. Миграция: поля `Item.priceKopecks/note`, `Operation.documentDate`, `WarehouseInventory.lastReceiptAt`.
2. Бэкфилл: `documentDate = createdAt` для всех операций; `lastReceiptAt = MAX(createdAt)` среди приёмок позиции.
3. Существующие позиции получают цену 0; после внедрения — отчёт «позиции без цены» и заполнение через справочник.
4. Перед миграцией на `C:\OSPanel\home\hotel` — бэкап БД.

## 3. Логика расчёта

| Место | Формула |
|---|---|
| Стоимость остатка склада | `qty × Item.priceKopecks` |
| Стоимость остатка номера | `qty × Item.priceKopecks` |
| Стоимость расхождения инвентаризации | `delta × Item.priceKopecks` |
| Дата поступления | `WarehouseInventory.lastReceiptAt` (последняя приёмка) |
| Дата документа | `Operation.documentDate` (выбирается при приёмке, иначе сегодня) |

Округление: деньги хранятся в копейках, все суммы — целые; в UI деление на 100 с двумя знаками.

## 4. Изменения интерфейса

### 4.1 «Номера»

- Кнопка **«Удалить»**; удаление разрешено только если у номера нет операций, остатков, инвентаризаций, задач уборки. Иначе — сообщение и предложение деактивировать.
- Подтверждение удаления.

### 4.2 Новый раздел «Справочник» (`/admin/catalog`)

- Таблица: название, категория, единица, цена, примечание, текущий остаток, действия.
- Добавление/редактирование: название, категория, единица, цена (₽), примечание.
- Удаление: только при остатке 0 и отсутствии операций/инвентаризаций; иначе деактивация.
- Поиск/фильтр по категории; кнопка «На склад» с предзаполнением.

### 4.3 «Склад»

- Колонки: позиция, категория, остаток, **цена**, **стоимость**, **дата поступления** (скрывается настройкой).
- Блок «Добавить на склад»: позиция из справочника, количество, цена (из справочника, видна), дата поступления, примечание → приёмка.
- Показаны итоги: стоимость склада.

### 4.4 Приёмка / раздача / возврат / списание

- Приёмка: позиции из справочника, цена видна, дата поступления, комментарий.
- Раздача/возврат/списание: **без цены**; дата документа показывается/скрывается.
- Списки операций: колонка «Дата» (скрываемая).

### 4.5 Инвентаризация

- Колонки: позиция, учёт, факт, расхождение, **цена**, **сумма расхождения**, **дата поступления** (скрываемая).
- Итог: сумма недостачи/излишка.
- В кабинете горничной — только количества.

### 4.6 Отчёты и Excel (8B)

- Остатки: количество, цена, стоимость, дата поступления.
- Движения: дата, позиция, количество, цена, сумма.
- Низкий остаток: + стоимость.
- Инвентаризация: расхождения в количестве и сумме.
- Excel: новые колонки и лист «Оценка склада».

### 4.7 1С (8B)

В DTO операций добавляются `documentDate`, `unitPrice`, `total` (необязательные; старый адаптер продолжает работать).

### 4.8 Настройки

- Раздел «Настройки» (или блок на складе): переключатель «Показывать даты в документах» (`settings.ui`).
- При выключении даты скрыты везде, где отображаются; данные не удаляются.

## 7. Риски

1. **Историческая стоимость** пересчитывается при изменении цены — следствие выбранного варианта; фиксируется в ТЗ.
2. **Удаление** — только без истории; иначе деактивация (аудит сохраняется).
3. **Миграция** — существующие позиции с ценой 0; нужен отчёт и заполнение.
4. **Дата** — «дата документа» может отличаться от даты создания; в отчётах используем `documentDate`.
5. **Копейки** — все суммы целые, форматирование только в UI.

Если позже понадобится историческая себестоимость — добавляются партии (`StockBatch`) и FIFO отдельным этапом; текущие данные (позиции, операции, остатки) сохраняются, цены в справочнике остаются «текущими».
