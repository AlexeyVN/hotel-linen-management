## 4. Где мы расходимся с ТЗ и с рынком

1. **ТЗ не обещало уборку.** В v2.3 нет ни слова о статусах номера, задачах и чек-листах — это честный учёт белья. Значит, «несоответствие» источникам — не дефект реализации, а **граница объёма**.
2. **Но мобильный экран без задач неполон.** Горничная в таких продуктах открывает «задания на день», а у нас — «инвентаризацию» и «раздачу». Наш экран решает учётную задачу, но не отвечает на вопрос «что мне делать сегодня и в каком порядке».
3. **Нет статуса номера — нет обратной связи администратору.** Мы знаем остатки, но не знаем «номер чистый/грязный/инспектирован». Для отеля это важнее учёта полотенец.
4. **Пересечение по списанию инвентаря.** TeamJet умеет списывать расходники при уборке — это пересекается с нашим модулем. Если отель уже на TeamJet/PMS, полная разработка хаускипинга создаст дубль процессов.
5. **Без PMS задачи нужно создавать вручную или по расписанию.** У нас нет заездов/выездов, поэтому «выездная уборка» не может появиться автоматически. Это ограничение любой автономной системы.

## 5. Что даст максимум ценности за минимум работы

Порядок по соотношению «ценность / трудозатраты»:

1. **Статус номера** (`CLEAN`, `DIRTY`, `INSPECTED`, `OUT_OF_ORDER`) + «грязный после выезда» вручную. Дешёво: одно поле и переключатель в мобильном и админском экране.
2. **Задачи на уборку** (`CleaningTask`: номер, тип, приоритет, исполнитель, статус, план/факт времени). Средняя цена: новый модуль, но переиспользует комнаты, права, PWA и офлайн-очередь.
3. **Чек-лист с фото к задаче** (шаблон → пункты → ответы + фото). Средняя/высокая цена: новые таблицы, UI прохождения, запрет завершения.
4. **Смена** («начать день») + фильтр «только мои задачи». Дешёво, усиливает 2.
5. **Отчёт по задачам**: сколько выполнено, среднее время, доля с фото. Средняя цена на базе готового Excel.
6. Автораспределение, нормативы, PMS-импорт, push — **дорого и рискованно**, без них можно жить на старте.

## 7. Что именно поменять в ТЗ, если выбираете 1 или 2

Добавить раздел «Хаускипинг (уборка номеров)» в v2.4:

- **Модели**: `RoomStatus` (или поле в `Room`), `CleaningTask` (roomId, type, priority, status, assigneeId, plannedMinutes, startedAt, finishedAt), `ChecklistTemplate`/`ChecklistItem`, `ChecklistRun`/`ChecklistAnswer` (ответ, фото, комментарий), `Shift` (начало/конец смены).
- **Типы уборки**: ежедневная, выездная, генеральная (настраиваемый справочник, как `RoomType`).
- **Статусы**: NEW → ACCEPTED → IN_PROGRESS → DONE (+ CANCELLED, POSTPONED); номер: DIRTY → CLEAN → INSPECTED, отдельно OUT_OF_ORDER.
- **Правила**: задачу нельзя завершить без чек-листа; фото на пункте — обязательное/опциональное (флаг).
- **Роли**: горничная — свои задачи; супервайзер — распределение и инспекция; администратор — всё.
- **Отчёты**: по задачам и времени, доля фото, Excel.
- **Явно вне объёма**: бронирования/гости, минибар, тарифы, push (или push отдельным решением).

При варианте 3 вместо моделей задач — контракт обмена: `pullRoomStatuses`, `pushCleaningResult` (по аналогии с `ErpAdapter`).

## 9. Acceptance-набросок для варианта 1

- Горничная нажимает «Начать смену» → видит только свои задачи, отсортированные по приоритету.
- Задача содержит номер, тип, время, чек-лист; завершение без чек-листа невозможно; фото на обязательных пунктах требуется.
- Завершение задачи меняет статус номера на CLEAN; супервайзер переводит в INSPECTED.
- Админ видит доску задач и отчёт: выполнено/в работе, среднее время, доля с фото.
- Офлайн: задача и чек-лист открываются без сети, ответы уходят в очередь и применяются ровно один раз.
- Существующий учёт белья не ломается: инвентаризация и раздача работают как раньше.
