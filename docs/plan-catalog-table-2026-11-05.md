# План: адаптивная таблица справочника позиций

Дата: 2026-11-05. Статус: **реализовано и выложено на `https://hotel`** (утверждены: скрытие колонок + прокрутка, иконки действий, только справочник, шрифт 13→14 px).
Проблема: в «Справочнике позиций» сливаются столбцы «Цена / Остаток / Примечание»; на узких экранах появляется горизонтальная прокрутка всей страницы.

---

## 1. Диагностика (замеры на развёрнутом приложении)

Замеры `getBoundingClientRect`/`scrollWidth` на `https://hotel/admin/catalog`:

| Ширина окна | Название | Цена | Остаток | Примечание | Действия | Ширина таблицы | Прокрутка страницы |
|---|---|---|---|---|---|---|---|
| 1440 | 229 | 86 | 81 | 177 | **380** | 1102 | нет |
| 1280 | 196 | 74 | 69 | 151 | **325** | 942 | нет |
| 1024 | **88** | 54 | 54 | 87 | **289** | 686 | нет |
| 768 | 88 | 54 | 54 | 87 | 289 | 685 | **916 > 768** |
| 390 | 88 | 54 | 54 | 87 | 289 | 685 | **718 > 390** |

Шрифт таблицы везде 14 px, `overflow-x` у контейнера — `visible`.

**Причины:**
1. Таблица `w-full` без минимальной ширины и `table-fixed` — браузер сжимает все колонки, кроме блока действий.
2. Колонка действий (3 текстовые кнопки) занимает 289–380 px — больше, чем «Название», «Цена», «Остаток» и «Примечание» вместе.
3. Нет `whitespace-nowrap` у чисел и заголовков, нет ограничения ширины примечания — текст «прилипает» к соседям.
4. Нет контейнера прокрутки: на узком экране таблица растягивает страницу, а не прокручивается внутри себя.
5. Шрифт не адаптируется, но уменьшать его — не решение: при 54 px колонка не читается даже 12-м шрифтом.

---

## 2. Лучшие практики (с источниками)

1. **Семантика таблицы важнее внешнего вида.** Заголовки — `<th scope="col">`, у таблицы — caption/скрытое описание. Это нужно скринридерам и альтернативным способам отображения ([W3C WAI Tables Tutorial](https://www.w3.org/WAI/tutorials/tables/)).
2. **Горизонтальная прокрутка таблицы допустима, если она внутри контейнера.** WCAG 1.4.10 Reflow делает исключение для таблиц, но требует, чтобы остальная страница не получала двумерную прокрутку; таблица должна скроллиться в своём контейнере, а не растягивать страницу ([W3C Understanding 1.4.10](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)).
3. **Самый безопасный базовый приём — не ломать таблицу, а добавить scroll-контейнер.** Так рекомендуют Access4all ADG и Adrian Roselli; карточная раскладка требует ARIA и сложнее в поддержке ([ADG Responsive tables](https://github.com/Access4all/adg/blob/3679f087960ad8b944bb2f64758eb26b2c7dbf87/pages/examples/tables/responsive/README.md), [Adrian Roselli](https://adrianroselli.com/2020/11/under-engineered-responsive-tables.html)).
4. **Не уменьшать шрифт, чтобы впихнуть данные.** Мелкий шрифт ухудшает читаемость и не проходит масштабирование; адаптивность достигается раскладкой, ширинами и скрытием второстепенных колонок. Размер текста таблицы — не ниже 12–13 px, лучше 13–14 px.
5. **Числа — вправо, `tabular-nums`, без переносов; заголовки — без переносов.** Примечание — `truncate` с доступом к полному тексту (`title`/редактирование), а не перенос на 3 строки.
6. **Действия компактно.** Три текстовые кнопки в строке — главный пожиратель ширины; иконки с `aria-label`/tooltip дают ту же функциональность при 100–140 px.
7. **Не использовать `vw`/`clamp()` для текста таблицы.** При зуме 200–400% это ломает читаемость; адаптивность — через breakpoint-классы Tailwind (`text-[13px] xl:text-sm`).

## 3. Предлагаемое решение

### 3.1 Раскладка по breakpoints

| Диапазон | Поведение |
|---|---|
| ≥1280 px | Полная таблица, фиксированные ширины колонок, шрифт 14 px |
| 768–1279 px | Таблица в контейнере с горизонтальной прокруткой, `min-width: 900px`, шрифт 13 px, заголовки 12–13 px |
| <768 px | Скрыть «Категория» и «Ед.»; «Примечание» показывать второй строкой под названием; действия — иконки; `min-width: 520px`, прокрутка только внутри контейнера |

На всех ширинах: `th scope="col"`, числа `text-right whitespace-nowrap tabular-nums`, заголовки `whitespace-nowrap`, примечание `truncate` + `title`, первая колонка `sticky left-0` с фоном при прокрутке.

### 3.2 Ширины колонок (colgroup)

| Колонка | Ширина |
|---|---|
| Название | 24% (min 180) |
| Категория | 12% (скрывается <768) |
| Ед. | 6% (скрывается <768) |
| Цена | 12%, вправо |
| Остаток | 12%, вправо |
| Примечание | 24% (на <768 уходит под название) |
| Действия | 10%, иконки 32×32 |

Итого `min-width` таблицы ~900 px на планшете; на телефоне после скрытия колонок — ~520 px.

### 3.3 Типографика

- Таблица: `text-[13px] xl:text-sm` (13 → 14 px), line-height 1.4.
- Заголовки: `text-xs xl:text-[13px]`, uppercase не делаем (русский текст).
- Примечание: 13 px, `truncate`, полный текст — в `title` и при редактировании.
- Поля ввода в режиме редактирования: `text-sm`, ширина по колонке, без горизонтального «выпирания».
- Ничего меньше 12 px; `clamp()`/`vw` не используем.

### 3.4 Действия

- Компактные иконки: «Изменить» (карандаш), «Выключить/Включить» (питание), «Удалить» (корзина) — инлайн-SVG без новой зависимости, `aria-label` + `title`.
- В режиме редактирования — «Сохранить»/«Отмена» текстом (временно шире, строка одна).
- На телефоне — те же иконки 36×36 для касания.

### 3.5 Что не делаем

- Не превращаем таблицу в карточки на телефоне в этом этапе (сложнее + ARIA; можно следующим шагом).
- Не трогаем другие таблицы (склад, отчёты, горничные) — вынесем в отдельный этап с общим компонентом.

## 5. Критерии приёмки

| # | Проверка | Ожидание |
|---|---|---|
| 1 | 1440/1280 | Все колонки читаемы, заголовки не сливаются, числа вправо, примечание не наезжает на остаток |
| 2 | 1024 | Нет слипания; таблица либо влезает, либо скроллится внутри контейнера |
| 3 | 768/390 | `document.documentElement.scrollWidth ≤ innerWidth`; скролл только у контейнера таблицы |
| 4 | <768 | Категория/ед. скрыты, примечание видно под названием, действия доступны |
| 5 | Редактирование | Поля ввода не выходят за колонки, сохранение/отмена работают |
| 6 | Доступность | `th scope="col"`, у иконок `aria-label`, полный текст примечания доступен |
| 7 | Регрессия | build + тесты зелёные; Playwright 0 ошибок; другие страницы не затронуты |

## 6. Вопросы на утверждение

| # | Вопрос | Варианты | Рекомендация |
|---|---|---|---|
| 1 | Поведение на телефоне | скрыть второстепенные колонки + прокрутка / карточки / только прокрутка | **скрыть + прокрутка** (меньше риск, данные доступны) |
| 2 | Кнопки действий | иконки с подсказками / короткие текстовые кнопки / меню «⋯» | **иконки** (освобождает ~250 px) |
| 3 | Объём | только «Справочник» / сразу все таблицы админки | **только справочник**, затем общий компонент |
| 4 | Шрифт | 13→14 px по breakpoint / fluid `clamp()` | **breakpoint** (предсказуемо при зуме) |

## 7. Реализация и проверка

- Реализовано в `components/catalog-admin.tsx`, плюс `min-w-0` в `components/admin-shell.tsx`.
- Замеры после правки: на 1440/1280/1024/768/390 `document.documentElement.scrollWidth` равен ширине окна; таблица прокручивается внутри контейнера; заголовки не перекрываются; на 390 «Категория/Ед./Примечание» скрыты, примечание под названием; редактирование на 390 не даёт переполнения.
- Скрипт проверки: `scripts/ui-catalog-responsive.mjs`; скриншоты `catalog-1440.png`, `catalog-1024.png`, `catalog-390.png`.
- Тесты: 82/82, build успешен; правки только UI, API/БД не менялись.
- Остальные таблицы админки на 390 пока переполняются — вынесено в следующий этап.
