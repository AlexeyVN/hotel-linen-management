# Эксплуатация

Инструкция для администратора, менеджера и горничной: ежедневные операции, настройки, контроль и восстановление.

---

## 1. Роли и доступ

| Роль | Код | Что может |
|---|---|---|
| Администратор | `ADMIN` | всё: пользователи, роли, 1С, настройки, логотип/цвет, отчёты, справочник, операции |
| Менеджер | `MANAGER` | номера — только просмотр; склад, справочник, приёмка, раздача, возврат, списание, инвентаризация, уборка, отчёты, 1С, общие настройки; без пользователей/ролей/логотипа |
| Горничная | `MAID` | только свои номера: инвентаризация, раздача, фото, задачи уборки; без склада/списания/отчётов |

Вход: `https://<домен>/login`. После входа ADMIN/MANAGER попадают в `/admin`, горничная — в `/m`.

Демо-учётки из seed: `admin/Admin123!`, `manager/Manager123!`, `maid/Maid123!`. **Смените пароли** в первый день.

## 2. Ежедневный цикл

### 2.1 Приёмка

1. «Документы → Приёмка».
2. Добавить строки: позиция, количество, дата поступления.
3. Проверить сумму/склад, провести.
4. Операция атомарна: остаток и очередь 1С обновляются вместе.

Ошибка «Недостаточно…» относится к раздаче/списанию, не к приёмке. Повторное проведение с тем же `clientOpId` не удваивает остаток.

### 2.2 Раздача в номер

1. «Документы → Раздача».
2. Выбрать номер и позиции, указать количество.
3. Провести. Если остатка не хватает — операция отклоняется целиком.
4. Горничная видит назначенные номера; менеджер — все.

### 2.3 Возврат

1. «Документы → Возврат».
2. Номер → позиции → количество.
3. Провести; остаток номера уменьшается, склад увеличивается.

### 2.4 Списание

1. «Документы → Списание».
2. Источник: склад или номер.
3. Причина обязательна: порча, износ, загрязнение, утеря, бой или свой текст.
4. Провести. QR позиции при списании **не удаляется** — удаляется только при удалении позиции из справочника.

### 2.5 Инвентаризация

1. «Документы → Инвентаризация» → создать по номеру.
2. Заполнить фактические количества; можно сохранить черновик и вернуться.
3. Фото — по желанию (камера на телефоне).
4. «Применить»: создаётся операция `AUDIT`, остаток номера корректируется, расхождения фиксируются.
5. После применения правки запрещены; новая инвентаризация — новое исправление.

### 2.6 QR-коды

- «Документы → QR-коды»: выбрать номер/позицию, формат (URL/JSON/текст), PNG/SVG, размер.
- «Сгенерировать и сохранить» — метка сохраняется в БД и `storage/qr`.
- Печать листа номеров/позиций — из сохранённых меток.
- Сканирование: камера или ручной ввод на `/m/scan`.
- При смене номера/`externalId`/домена метка «устаревает» — перегенерируйте вручную.
- Удаление QR — только вместе с позицией/номером из справочника.

### 2.7 Уборка и чек-листы

1. «Уборка»: создать задачу на номер, тип (ежедневная/по требованию/генеральная), приоритет, исполнителя.
2. Создание задачи помечает номер грязным; завершение — чистым (кроме «в ремонте»).
3. «Чек-листы»: шаблоны с пунктами; обязательные фото; задачу нельзя завершить, пока чек-лист не закрыт.
4. «Горничные»: смены, закреплённые номера, план на дату, архив.
5. Мобильный кабинет `/m`: дашборд, задачи, номера, инвентаризация, раздача.

### 2.8 Отчёты и Excel

- «Отчёты»: остатки, движения за период, дефицит, позиции без цены, уборка, горничные.
- Кнопка Excel: файл с логотипом, названием отеля, датой, «Составил», ответственным и местом для подписи.
- Движения фильтруются по дате документа.
- Печатная форма: A4, ориентация по числу колонок, повтор заголовков.

### 2.9 Пользователи

- «Настройки → Пользователи» (ADMIN).
- Создание: логин, ФИО, пароль, роль.
- «Изменить ФИО / логин» — правка существующего; логин уникален.
- Смена роли, деактивация, сброс пароля, назначение номеров горничной.
- Смена своего логина не завершает сессию; следующий вход — с новым логином.

### 2.10 Настройки

- «Настройки → Общие настройки»: показывать даты; логотип, цвет, печатные реквизиты; название отеля сразу меняет title вкладки, Apple title и webmanifest.
- Логотип: PNG/JPEG/WebP, автоматически уменьшается до 1600 px и сохраняется PNG с прозрачностью; только ADMIN.
- Цвет: 8 пресетов или HEX; слишком светлый цвет отклоняется (контраст < 4.5:1).
- Порядок меню: «Общие настройки → Номера и типы комнат → Пользователи → Роли → Интеграция 1С»; MANAGER видит доступные пункты, номера — только просмотр.

## 4. Резервное копирование

Ежедневно:

```cmd
deploy\backup.cmd
```

Linux:

```bash
sqlite3 app/data/app.db "VACUUM INTO 'backups/app-$(date +%Y%m%d-%H%M%S).db'"
```

Хранить копии вне сервера, вместе с `app/storage/` (фото, QR, логотип).

Восстановление:

1. Остановить Node.
2. `deploy\restore.cmd app\backups\<файл>.db` (Windows).
3. Проверить `PRAGMA integrity_check` и войти.
4. Запустить сервис.

## 5. Интеграция 1С

- Настройки: включена/выключена, режим, базовый URL, логин, пароль, интервал синхронизации.
- Пароль хранится зашифрованным (AES-256-GCM, ключ из `NEXTAUTH_SECRET`).
- Воркер стартует с приложением и раз в минуту отправляет `PENDING` из `OutboxEntry` и `RoomStatusEvent`; ретраи до 8 попыток.
- Ручные действия: проверка соединения, «Загрузить номенклатуру», «Отправить очередь», «Отправить статусы».
- «Загрузить номенклатуру» импортирует только позиции (`GET /hs/hotel/items`); статусы номеров и операции она не трогает.
- Статусы номеров: включить «Обмен статусами», передать в 1С URL webhook и `X-Webhook-Token`, указать путь/метод SetRoomStatus. Webhook обновляет только статус, задача уборки не создаётся.
- Изменения статуса в приложении (создание задачи → DIRTY, завершение → CLEAN, ручной статус) ставятся в очередь и уходят в 1С.
- Внешний триггер: `POST /api/integration/worker` с `Authorization: Bearer <INTEGRATION_WORKER_TOKEN>`.
- Если 1С недоступна, учёт продолжается локально; очередь растёт.
- Точный контракт Housekeeping/SetRoomStatus и наличие webhooks нужно подтвердить у внедренца 1С; проверяйте на тестовом контуре.

## 6. Типовые проблемы

| Проблема | Решение |
|---|---|
| Забыт пароль | ADMIN сбрасывает в «Пользователи»; войти и сменить |
| Нет доступа к разделу | Проверить роль/права в «Роли»; горничная видит только свои номера |
| «Недостаточно на складе» | Проверить остаток и количество; операция не проведена |
| Не завершается уборка | Закрыть все пункты чек-листа и обязательные фото |
| QR ведёт на старый адрес | Сменить `NEXTAUTH_URL`, проверить статус метки, перегенерировать |
| Логотип не загружается | Только PNG после обработки; ≤2 МБ; ADMIN |
| Цвет не применяется | Выбрать цвет и нажать «Применить цвет»; контраст ≥4.5:1 |
| PWA не устанавливается | HTTPS и доверенный сертификат |
| Webhook 1С → 401 | Проверить `X-Webhook-Token`; токен перегенерирован — обновить в 1С |
| Webhook → 503 | Включить «Обмен статусами» и задать токен |
| Webhook → 400 | Проверить номер, статус, `occurredAt`; неизвестный статус не применяется |
| Статусы не уходят | Включены интеграция и обмен, заполнен путь, проверить «Отправить статусы» и лог |
| 1С не отправляет | Проверить настройки, лог, воркер, токен |
| Долго открывается | Проверить Node/прокси, размер фото, свободное место |

Логи: `app/logs/server.log`. Бэкапы: `app/backups/`.

## 7. Безопасность

- Сменить демо-пароли; не публиковать `.env` и БД.
- Ограничить доступ к `app/data`, `app/storage`, `app/backups`.
- Использовать HTTPS; не открывать 3000 в интернет напрямую.
- Регулярно обновлять Node/зависимости и проверять `npm audit`.
- Уволенных сотрудников деактивировать, а не удалять (история сохраняется).
- Не передавать `NEXTAUTH_SECRET` и пароль 1С.
