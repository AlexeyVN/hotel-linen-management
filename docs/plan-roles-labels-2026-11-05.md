# План: русские подписи прав на странице «Роли»

Дата: 2026-11-05. Статус: **реализовано и выложено на `https://hotel`**.
Утверждено: вариант A (перевод + удаление кодов прав), коды ролей оставить, порядок Администратор → Менеджер → Горничная.
Запрос: проверить английские значения чекбоксов на странице «Роли», заменить на русские, провести аудит.

---

## 1. Аудит текущей страницы

Скриншот: `app/screenshots/roles-before.png`.

| # | Замечание | Серьёзность | Причина |
|---|---|---|---|
| 1 | `catalog.manage` выводится сырым ключом дважды | высокая | нет записи в `PERMISSION_LABELS` → fallback `code` |
| 2 | `cleaning.manage` и `cleaning.execute` — сырые ключи | высокая | то же |
| 3 | `settings.ui` и `settings.branding` — сырые ключи | высокая | то же |
| 4 | У каждого чекбокса справа виден английский код (`rooms.read`, `warehouse.receive` и т.д.) | высокая | второй `<span>{code}</span>` в компоненте |
| 5 | В заголовках ролей видны `(ADMIN)`, `(MANAGER)`, `(MAID)` | средняя | технический код в `CardTitle` |
| 6 | Порядок карточек: Администратор, Горничная, Менеджер | средняя | порядок из API/БД, не бизнес-иерархия |
| 7 | 19 чекбоксов идут одним списком без групп | средняя | нет категорий; сложно сканировать |
| 8 | Заблокированные права ADMIN визуально только серые | низкая | нет пояснения/иконки замка |
| 9 | Русские подписи хранятся в компоненте, отдельно от `PERMISSIONS` | средняя | риск снова получить fallback при новом праве |
| 10 | Нет теста, что каждое право имеет русскую подпись | средняя | регрессия не ловится |

Итого: **5 из 19** прав (26%) не переведены; английские коды выводятся **57 раз** (19 × 3 роли) как второй текст.

## 3. Варианты

### Вариант A — минимальный (рекомендуется для быстрого исправления)

- Добавить 5 недостающих подписей.
- Убрать английский код из строки чекбокса; оставить только русскую подпись.
- Убрать коды `(ADMIN)/(MANAGER)/(MAID)` из заголовков.
- Отсортировать карточки: Администратор → Менеджер → Горничная.
- Вынести карту подписей в `lib/permission-labels.ts` + тест на полноту.

Плюсы: закрывает жалобу, малый diff, без риска для логики.
Минусы: 19 пунктов остаются плоским списком.

### Вариант B — A + смысловые группы

Дополнительно сгруппировать:

```
Номера
  Просмотр номеров
  Управление номерами и типами
Склад
  Просмотр склада
  Приёмка
  Управление справочником
Документы
  Раздача, Возврат, Списание, Инвентаризация
Уборка
  Управление уборкой
  Выполнение задач уборки
Отчёты
  Отчёты
Администрирование
  Пользователи, Роли, 1С, Минимальные остатки, Общие настройки, Брендинг
Фото
  Просмотр фото
```

Плюсы: лучше сканируется. Минусы: больше вёрстки и тестов.

### Вариант C — оставить коды как подсказку

Русская подпись + английский код в `title`/tooltip. Не рекомендуем: на телефоне tooltip недоступен, а визуальный шум остаётся.

**Рекомендация: A**, при желании — сразу B.

2. Все 19 прав имеют осмысленную русскую подпись.
3. Заголовки ролей — только русские названия.
4. Порядок карточек: Администратор → Менеджер → Горничная.
5. Сохранение прав работает; блокировка `users.manage`/`roles.manage` у ADMIN сохранена.
6. Тесты/build зелёные; мобильная ширина без переполнения.
