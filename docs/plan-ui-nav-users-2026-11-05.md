# План: навигация, оформление и управление пользователями

Дата: 2026-11-05. Статус: **реализовано и выложено на `https://hotel`**.
Утверждено: «Склад» + «Документы», группа «Настройки» в сайдбаре, 8 пресетов + HEX, редактирование ФИО/логина, переименование только списка.
Запрос: цвет подсветки из палитры; загрузка логотипа в настройках; объединение пунктов в «Документы»; перенос 1С/Пользователей/Ролей в «Настройки»; редактирование ФИО и логина пользователей; переименование «Пользователи и роли» / «Список» в «Пользователи».

Порядок — по циклу работы: настроить номенклатуру → принять → увидеть остаток → раздать → вернуть → списать → сверить → напечатать метки.

### Вариант B — UX-уточнение: две группы

```

  Склад
Документы
  Приёмка

```

«Справочник» и «Склад» — это справочники/состояние, а не документы; «Документы» — операции и печать. Семантически точнее, но появляется вторая группа.

### Вариант C — плоский список с разделителями

Минимальные изменения, но 17 пунктов остаются.

**Рекомендация:** A — точно по запросу; если важна семантика — B. В обоих случаях «Уборка» и «Настройки» — раскрывающиеся группы, URL не меняются.

### Поведение групп

- Группа раскрыта, если активен дочерний пункт; иначе свёрнута.
- Заголовок группы — кнопка с `aria-expanded`; дети — ссылки.
- Если у роли нет доступа ни к одному дочернему пункту — группа скрыта.
- На мобильном: группы показываются секциями с заголовками; активный пункт виден, лишние не ломают горизонтальный скролл.
- «Настройки»: дочерние «Общие настройки» (`/admin/settings`), «1С», «Пользователи», «Роли»; переходы по существующим URL.

## 3. Настройки оформления

### 3.1 Единый блок «Оформление» (ADMIN)

В `/admin/settings`:

1. **Логотип** — уже есть: превью на шахматном фоне, загрузка/замена/удаление; если логотипа нет — кнопка «Загрузить логотип».
2. **Цвет подсветки** — палитра из 8 цветов, сохранение в `Setting` `ui.accentColor` (id цвета).
3. **Печатные реквизиты** — название отеля, ФИО/должность ответственного (уже есть).

### 3.2 Палитра

Только предустановленные цвета (без произвольного hex), тёмные оттенки с белым текстом — контраст ≥ 4.5:1:

| id | Название | HSL для `--primary` |
|---|---|---|
| blue | Синий (по умолчанию) | `221 83% 53%` |
| indigo | Индиго | `243 75% 59%` |
| violet | Фиолетовый | `262 83% 58%` |
| teal | Бирюзовый | `175 84% 26%` |
| emerald | Изумрудный | `160 84% 26%` |
| amber | Янтарный | `26 90% 37%` |
| rose | Розовый | `347 77% 42%` |
| slate | Графит | `215 25% 27%` |

Применение: RootLayout (server) читает `ui.accentColor`, ставит на `<body>` CSS-переменные `--primary` и `--primary-foreground` (белый). Это меняет кнопки, активные пункты меню, ссылки, фокус-ринг и прогресс-бары без правки каждого компонента.

Сохранение — через `settings.updateAccent` (право `settings.branding`, только ADMIN) + `router.refresh()`; страница входа тоже получает цвет.

### 3.3 Логотип

Новых требований нет: загрузка уже реализована; в блоке «Оформление» она остаётся и показывается всегда, даже если логотипа нет. Тест на прозрачность/масштабирование сохраняется.

## 4. Пользователи: редактирование ФИО и логина

### 4.1 API

Новый `users.updateProfile` (право `users.manage`):

```
{ userId, login?, fullName? }
```

- `fullName`: trim, 2–120 символов.
- `login`: trim/lowercase, 4–32, `[a-z0-9._-]`, проверка уникальности (P2002 → «Логин уже занят»).
- Нельзя очистить оба поля; пустые значения отклоняются.
- Аудит: запись в лог (кто изменил кого), без паролей.
- Смена своего логина разрешена: текущая сессия остаётся, следующий вход — с новым логином. В UI — предупреждение.

### 4.2 UI

- В строке пользователя — кнопка «Изменить» (карандаш): inline-поля «ФИО» и «Логин», кнопки «Сохранить»/«Отмена».
- После сохранения список обновляется; в шапке админки новое ФИО появится сразу (getCurrentUser читает БД).
- Ошибка уникальности/валидации — текстом под полями.
- H1 остаётся **«Пользователи и роли»**; CardTitle — **«Пользователи (N)»** (вместо «Список (N)»).
- Роли остаются отдельной страницей `/admin/roles` (в группе «Настройки»).

### 4.3 Ограничения

- Смена логина не разлогинивает текущую сессию; это осознанно (JWT по id).
- Пароль — отдельной кнопкой, как сейчас; смена пароля не входит в inline-редактирование.

### Критерии приёмки

1. В меню 5 верхних групп; «Документы» содержит 8 пунктов в согласованном порядке; «Настройки» — 4.
2. Группа раскрывается, активный пункт подсвечен; скрытые по правам пункты не показываются.
3. Цвет выбирается из 8 образцов и сразу применяется к кнопкам/активному меню/фокусу на всех страницах, включая логин.
4. Логотип загружается/удаляется в том же блоке; при отсутствии видна кнопка загрузки.
5. ADMIN меняет ФИО и логин всех трёх пользователей; пустые/невалидные/занятые значения отклоняются.
6. H1 и список называются «Пользователи» / «Пользователи (N)».
7. Роли/1С/Пользователи доступны из «Настроек»; прямые URL работают.
8. Тесты (84+) и build зелёные; мобильная навигация без горизонтального переполнения страницы.

## 6. Риски

1. **Группировка** может усложнить поиск: лечится раскрытием активной группы и сохранением URL.
2. **Цвет** — только тёмные оттенки; произвольный hex не даём, чтобы не получить нечитаемый текст.
3. **Смена логина** не завершает сессию; предупреждаем в UI.
4. **Права**: группы и блок оформления скрываются, если нет прав; API проверяет права независимо.
5. **Мобильное меню**: аккордеон в горизонтальной панели может быть тесным; проверяем на 390 px.
