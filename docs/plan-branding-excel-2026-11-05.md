# План: логотип отеля и печатные формы Excel

Дата: 2026-11-05. Статус: **реализовано и выложено на `https://hotel`**.
Утверждено: canvas→PNG ≤1600, логотип на логине и в админке, единый Excel-шаблон, «Составил» + ответственный из настроек, загрузка только ADMIN.

## 2. Логотип

### 2.1 Загрузка и нормализация

- Админ выбирает PNG/JPEG/WebP (SVG не принимаем — риск XSS и сложность растеризации).
- **Клиент** (страница настроек) декодирует изображение, уменьшает до max 1600×1600 с сохранением пропорций (не увеличивает), экспортирует **PNG** через canvas. Прозрачность сохраняется.
- Сервер принимает только PNG ≤ 2 МБ, проверяет сигнатуру и размеры из IHDR (защита от подмены), сохраняет в `storage/branding/logo.png`, обновляет `Setting`:
  - `branding.logoWidth`, `branding.logoHeight`, `branding.logoUpdatedAt`, `branding.logoVersion`;
  - `branding.hotelName`.
- Старый файл удаляется после успешной замены; ошибка `unlink` логируется.
- Удаление логотипа — отдельная кнопка (файл + ключи), возврат к текстовой шапке.

Почему клиентская нормализация: нет нативной зависимости `sharp` (Windows/антивирус), PNG гарантированно поддерживает альфа-канал и принимается ExcelJS. WebP/JPEG конвертируются в PNG автоматически.

### 2.2 Хранение и отдача

- Файл: `storage/branding/logo.png` (вне `public`).
- Публичный `GET /api/branding/logo?v=<version>` — нужен на странице входа до авторизации; отдаёт PNG с `Cache-Control` и ETag; при отсутствии — 404.
- Загрузка `POST /api/admin/branding/logo` и удаление `DELETE /api/admin/branding/logo` — только право `settings.branding` (ADMIN).
- Текстовые поля брендинга — через `settings.branding.get/update` (ADMIN).

### 2.3 Отображение и масштабирование

- Логин: логотип над названием, `max-h-14 max-w-[200px] object-contain`, прозрачный фон.
- Админка: логотип в шапке сайдбара, `max-h-10 max-w-[160px] object-contain`; при отсутствии — текущий текст.
- Проп `branding` из серверного layout/LoginPage (URL с версией для сброса кэша).
- Настройки: карточка «Логотип отеля» — превью, размеры, замена, удаление; предупреждение о прозрачности.
- `alt="Логотип отеля"`, `onError` → текстовая шапка (клиентский компонент).

### 2.4 Права

- Новое право `settings.branding` (всего 19), только ADMIN; MANAGER его не получает (в пресете исключить).
- Просмотр логотипа публичный (страница входа), изменение — только ADMIN.

## 3. Печатные формы Excel

### 3.1 Единый шаблон для всех выгрузок (рекомендуется)

Все существующие Excel-отчёты (остатки, движения, дефицит, без цены, уборка, горничные) получают общую печатную шапку и подвал:

```
[логотип]   Отель «...»                     Печатная форма
─────────────────────────────────────────────────────────
            Остатки склада
            на 05.11.2026
Дата формирования: 05.11.2026 14:20   Составил: Иванов И.И.
─────────────────────────────────────────────────────────
№ | Позиция | Категория | ... | Стоимость
...данные...
─────────────────────────────────────────────────────────
Ответственный: ____________________ / Петров П.П. /
Должность: главный менеджер
Дата: «___» __________ 20___ г.        Подпись: __________
```

- Логотип: PNG из `storage/branding`, вставка в верхний левый угол, `ext` не более 160×60 px, пропорции сохраняются по сохранённым width/height; прозрачность PNG сохраняется.
- Дата: дата формирования; для отчёта движений — ещё период «с … по …».
- Ответственные: «Составил» — текущий пользователь (ФИО из сессии); «Ответственный/Утвердил» — из настроек (`print.responsibleName`, `print.responsiblePosition`, опционально `print.directorName`).
- Место для подписи: пустые линии и подпись, не заполняются автоматически.
- Настройки печати: A4, ориентация по числу колонок (portrait для остатков/дефицита, landscape для движений/горничных), `fitToWidth: 1`, поля, повтор строки заголовков, область печати, нумерация страниц в футере.
- Без логотипа — шапка с названием отеля текстом (fallback).

### 3.2 Альтернатива: отдельные шаблоны под отчёт

Для каждого отчёта — свой набор колонок, титул и подписи (например, «Акт инвентаризации» с двумя подписями). Больше работы и дублирования; имеет смысл, если нужны юридические формы. Рекомендуется после универсального шаблона, при необходимости.

## 6. Риски

1. **Canvas-нормализация** может не сработать в старом браузере; показываем ошибку, сервер всё равно проверяет PNG.
2. **ExcelJS и WebP**: решено нормализовать в PNG на клиенте.
3. **Кэш логотипа**: URL с версией; после замены версия меняется.
4. **Печатная форма**: ориентация/масштаб подбираются по числу колонок; проверяем на реальном файле.
5. **Подписи** — только места для подписи, не ЭЦП; юридическая форма не гарантируется.
